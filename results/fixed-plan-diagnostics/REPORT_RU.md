# Диагностика фиксированного плана Mk10

Исходное расписание сохранено. Это замороженный исследовательский пример Mk10/list_v1, а не реальный план, утверждённый технологом предприятия.
Использованы 512 сохранённых калибровочных виртуальных прогонов F1. Срывов срока 412.5: 421. Новых прогонов, выбора другого расписания и исправлений в этом этапе нет.

Ожидания разложены без пересечений внутри операции: технологические предшественники сверх её планового старта; дополнительная очередь станка; ремонт после готовности к запуску; паузы уже начатой обработки. Времена после срока не приписываются завершению. Суммирование ожиданий разных операций не равно потерянному времени всей партии: задержка может передаваться по цепочке.

Это наблюдаемые задержки, а не доказательство, что исправление первого станка даст наибольший эффект. Календарь отказов и положение операций в цепочке могут совместно влиять на картину. Для причинного вывода нужен отдельный проверочный прогон с явно заданным вмешательством.
Последняя колонка суммирует ожидания разных операций: они могут происходить одновременно, поэтому сумма может превышать длительность партии. В CSV unstarted_at_deadline и unfinished_at_deadline для строки станка также являются счётчиками операций, а не числом независимых партий.
Обе временные колонки усреднены по всем 421 неуспешным партиям, включая нулевые задержки, а не только по партиям с отмеченным ремонтом. Приоритет «технология → дополнительная очередь → доступность» задаёт бухгалтерскую классификацию перекрывающихся ожиданий; причинное разложение не является уникальным.

Индексы начинаются с нуля; время — в исходных единицах задачи, 100 ticks = 1 единица. Альтернативная совместимость ещё не означает допустимость переноса в конкретное место очереди.
Следующий этап должен проверить локальное изменение очереди или назначения, сохранив остальные решения и технологические зависимости. Для него нужны проверка допустимости и новый независимый результат. Идеальная отмена поломки — только анализ чувствительности, а не обещанное физическое усиление.
В example.json сохранена наблюдаемая цепочка ожиданий для первого неуспешного прогона и первого незавершённого заказа. Выбор примера детерминирован, его показатели не являются отдельной независимой выборкой.

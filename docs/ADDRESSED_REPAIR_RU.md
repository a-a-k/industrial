# Адресное усиление ремонта

Дополнительный обязательный контроль C возвращает результат одной дешёвой комбинации без доказательного перебора. Он отдельно измеряется во всех пяти повторах как третий участник. Сравнение с B не может засчитать выигрыш за счёт ненужного доказательства минимума, если C уже дал тот же полезный результат. Требуется завершённая дешёвая комбинация у D, B и C; усечённая комбинация означает отсутствие научной победы в этом случае.

Для победы по числу станков нужны достаточные D/B/C во всех пяти повторах, k_D<k_B и k_D<k_C во всех повторах, TD<=1,25min(TB,TC). Для победы по цене нужны достаточные D/B/C, k_D=k_B, k_C>=k_D во всех повторах; цена референса — минимум B и C среди вариантов с таким же k. TD<=0,8 цены референса и D быстрее хотя бы в4/5пар. Любой именованный дешёвый вариант с k<=k_D, который FEASIBLE или UNRESOLVED, консервативно блокирует такую победу. Ветка надёжности также требует достаточный C и k_D<k_C во всех повторах. Полная цена включает отдельную фазу анализа графа/подготовки входов и независимую сертификацию выбранного решения; общие затраты учитываются симметрично. Предел120s проверяется строгим внешним watchdog, а не допускает дополнительные секунды. Каждый найденный допустимый вариант сохраняется сразу, включая пороговый ответ с ещё не вычисленным точным числом остальных успехов.

Равномерный контроль восстанавливает исходные календари на всех используемых станках. Пустые очереди не влияют на выпуск; их латентные записи сохраняются в сырых банках и исключаются из проверки идентичности производственно значимых координат. Для обеих проекций сохраняются SHA256. Это ограничение проверки не исключает ни одной операции или обязательного заказа.

Цель — найти конкретные станки, для которых ускорение ремонта обеспечивает вероятность выпуска всей партии к прежнему сроку не ниже95%, и сравнить полную цену поиска с сильным прямым контролем. Проверяются все Mk01–Mk10 и оба профиля отказов. Назначения, очереди, партия, исходный C0 и срок d=1,1C0 фиксированы.

На каждом используемом станке два действия: сохранить исходный ремонт либо уменьшить среднее экспоненциальной длительности ДО округления до25% исходного. Среднее времени работы до отказа2C0 сохраняется; ремонт0,1C0 или0,025C0, округление вверх к5ticks, минимум5ticks. Последующие начала отказов пересчитываются, вложение календарей не предполагается. Число затронутых станков — показатель объёма вмешательства, а не цена или число ремонтников.

F1 сохраняет независимые renewal-процессы. F2SI — явно заданное причинное расширение исходного F2: с вероятностью1/2 станки используют общие последовательности экспоненциальных случайных инноваций, но собственные масштабы ремонта и собственные renewal-часы. При одинаковых действиях календари совпадают с исходным F2. При разных действиях это общие инновации, а не неизменяемый внешний общий простой. Старые наблюдения F2 не идентифицируют, какая причинная интерпретация верна для реального предприятия. Все сравниваемые методы используют одно расширение.

На512 новых траекториях требуется не менее500 успехов. Две стратегии получают одинаковые календари, структуру, ограничения временных окон и локальный кэш точных ответов. Вначале обе выполняют одинаковую дешёвую комбинацию: префиксы по нагрузке и запасу, жадное добавление станков с полным просмотром одиночных действий, обратное удаление и просмотр пар. Затем D использует ленивый Boolean/CP-подбор; B — прямой перебор наборов по возрастанию числа вмешательств ниже лучшего известного решения, с остановкой после первого допустимого набора. Неиспользуемые станки исключаются одинаково.

Для сценария существенны все координаты, чьи два календаря различаются до срока. Ранее успешные сценарии также проверяются. Для неуспешного локального сочетания v добавляется точный запрет z_s<=sum(x_m!=v_m). Монотонные hitting-cuts не используются. Ограничения необходимых рабочих окон доступны обеим стратегиям. Если оптимистический master исключает все меньшие наборы, найден минимум на рабочем банке. Это стандартная sample-average Boolean/CP-оптимизация, а не новая эксклюзивная операция TSFG/SIMPAT и не доказательство минимума истинной вероятности.

Каждой стратегии выделяется120s на полный запрос: чтение, импорт, подготовку oracle, всю дешёвую комбинацию, кэш, solver/перебор и вывод. Лучшее проверенное решение сохраняется при исчерпании бюджета; отсутствие доказательства минимума обозначается отдельно. Пять пар процессов выполняются последовательно на одном runner/CPU с чередованием порядка. Регистрируются все решения всех повторов; выбор удачного повтора после теста запрещён.

Все20 рабочих результатов фиксируются общим seal до новых8192 независимых траекторий проверки. В семейство входят все уникальные физические наборы всех повторов, дешёвые контроли, исходный и равномерный варианты. Для N сочетаний две односторонние точные биномиальные границы используют alpha=0,05/(2N). Нижняя>=0,95 означает подтверждённую достаточность, верхняя<0,95 — подтверждённую недостаточность; остальные сохраняются как UNRESOLVED. Независимый DES и прямой RiskDAG сверяют все8192 исхода, исходный S1 — первые128 скалярных и16 полных трасс с физическими проверками. Вычислительная ошибка не является срывом производственного срока.

Научная победа допускается только при0<k_D<M_used во всех пяти повторах. Все парные решения должны подтвердить95%. Далее: либо D затрагивает меньше станков во всех пяти парах при медиане полной первой цены TD<=1,25TB; либо одинаковое число станков во всех парах при TD<=0,8TB и меньшем TD хотя бы в4/5пар. Альтернативная победа по надёжности требует D подтверждённо достаточен и B подтверждённо недостаточен во ВСЕХ пяти парах, k_D<=k_B и сопоставимую цену. Победа над неопределённым B не засчитывается. Полная цена включает компиляцию, необходимое окружение CP только для D, генерацию/разбор, весь поиск и независимую проверку результата. Общие передачи и подготовка раскрываются отдельно; все затраты входят в72runner-часа. Скорость характеризует эти пять измерений, а не отдельную95%-ю гарантию времени.

Меньшее вмешательство против одного равномерного ремонта само по себе не является сравнительной победой. Если нет побед против сильного прямого контроля, научный итог NOT_ESTABLISHED; допустимые адресные варианты публикуются отдельно без подмены критерия. Глобальная оптимальность, экономическая или реальная достижимость ремонта не заявляются. Сборки, зависимости, генерация, тесты, измерения и отчёты выполняются только на GitHub-hosted Actions.

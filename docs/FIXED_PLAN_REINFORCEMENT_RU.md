# Краш-тест фиксированного плана и проверка небольшого исправления

## Задача и проверяемое утверждение

Для Mk01–Mk10 сначала фиксируется сильный номинальный CP-план. Все методы получают один и тот же план, технологические зависимости, совместимость, законы отказов и сценарии. Проверяется, помогает ли диагностика найти одно допустимое небольшое изменение, повышающее вероятность выпуска всей партии к прежнему сроку. Отдельный вопрос — даёт ли диагностика лучший результат при сопоставимых полных затратах либо тот же результат дешевле сильных открытых контролей.

Номинальные планы являются исследовательскими примерами. Их нельзя называть планами реального предприятия, утверждёнными технологом. Сохранённые Mk01/Mk05/Mk10 не оптимизируются заново. Историческая стоимость их построения обозначается отдельно.

Полная серия содержит 20 условий: десять задач и два закона F1/F2. Техническая квалификация Mk10 не заменяет ни одно из них. Законы, начальное состояние, округление, шкала исходного C0, машины и состав партии сохраняются. Основной срок d=1,1C0. Истечение срока не отменяет работу; семантика неизвестного окончательного исхода сохраняется. Вычислительная недоступность не считается производственным неуспехом.

## Допустимые исправления

Исходные очереди должны уже иметь ранние допустимые номинальные времена при нулевых простоях. Иначе вход отвергается: скрытое сжатие всего расписания не выдаётся за локальное исправление.

Каталог содержит отсутствие изменений, все допустимые перестановки двух соседних операций одной очереди и по одной вставке для каждой пары «операция — другой совместимый станок». Для последней проверяются все позиции вставки, сохраняются относительные порядки остальных операций; заранее выбирается позиция с наименьшими номинальной длительностью, суммой абсолютных изменений плановых времён и индексом позиции, в таком порядке. Это предварительно отфильтрованный каталог, а не все возможные однооперационные переносы.

Для каждой правки заново рассчитываются ранние времена по объединённому графу технологических и машинных зависимостей. Циклы, нарушение совместимости и увеличение номинальной длительности относительно зафиксированного плана запрещены. Сохраняется полный diff назначения, очередей и времён. Удаляются только точные дубликаты физических назначений и очередей. Перестановки статистически одинаковых машин не служат основанием копировать результаты на календарях с физическими индексами.

## Подбор на 512 виртуальных прогонах

Для каждого условия создаются 512 независимых калибровочных сценариев с отдельным пространством идентификаторов. Каталог строится до их открытия. Никакая частота нового проверочного банка при подборе не используется.

Метод D оценивает чувствительность исходного плана: в неуспешных калибровочных прогонах отдельно убирает простои каждого станка и считает, сколько партий это спасает. Два станка с наибольшим числом спасённых партий задают область поиска; равенства разрешаются индексом станка. Если до срока простоя данного станка не было, повторный расчёт этого вмешательства не нужен. Успешные исходные прогоны не могут стать ещё одним спасённым неуспехом. Эти пропуски и их обоснование записываются.

Идеальная доступность — диагностическое вмешательство, а не осуществимое исправление или новый вероятностный режим F2. Оно может нарушать поддержку общего календаря F2. Перенос эффекта этого вмешательства на реальную правку не предполагается: он подлежит независимой проверке.

Из правок, затрагивающих два выбранных станка, берутся первые 31 по номинальной длительности, числу структурных изменений и идентификатору. Вместе с отсутствием изменений они оцениваются на всех 512 сценариях. Выбирается максимум успехов, затем минимум структурных изменений, номинальной длительности и идентификатора. При равенстве результата отсутствие изменений имеет приоритет.

## Открытые контроли

Все контроли используют тот же допустимый каталог и те же 512 сценариев.

| Метод | Заранее заданное правило |
|---|---|
| N | Исходный план без изменений |
| L | Лучшая номинальная правка; равенства: число изменений, идентификатор |
| S | 31 правка по статической нагрузке и резервам плюс отсутствие изменений; затем полные 512 прогонов |
| T | 31 правка по наблюдаемым прямым задержкам плюс отсутствие изменений; затем полные 512 прогонов |
| G | Все правки на первых 64 из тех же сценариев; 31 лучшая непустая правка плюс отсутствие изменений на всех 512 |
| D-DAG | В точности алгоритм D, вычисляемый прямым DAG-движком |

S сортирует сначала по максимальной нагрузке затронутых станков (сумма назначенной работы / номинальная длительность), по убыванию; затем по минимальному полному резерву затронутых операций, по возрастанию; затем по номинальной длительности и идентификатору. Резервы рассчитываются по объединённому номинальному графу при прежней номинальной длительности.

T использует сумму ожиданий ремонта после готовности и пауз обработки в неуспешных исходных прогонах. Оценка правки равна половине нормированной суммы по затронутым станкам плюс половине нормированной суммы по затронутым операциям. Каждая нормировка использует общую сумму своей категории; нулевой знаменатель даёт ноль. Сортировка: эта оценка по убыванию, номинальная длительность и идентификатор по возрастанию. Это воспроизводимая эвристика по наблюдаемой трассе, не причинная атрибуция.

G перебирает весь каталог в порядке «номинальная длительность, число изменений, идентификатор». Квота фиксирована: весь каталог × 64, затем не более 32 × 512. Неполное выполнение квоты означает незавершённый контроль; оно не заменяется более слабым правилом после просмотра результата. Финальный выбор для S/T/G использует те же критерии, что D.

S1 и прямой DAG получают одинаковую семантику исполнения. D и D-DAG должны выдавать одинаковые диагностику, оценки и решение. При полных наблюдениях full-R совпадает с частотой успехов: дополнительная прогнозная информация SIMPAT не заявляется. Потенциальная польза диагностической стратегии и стоимость её реализации S1 — разные результаты.

## Независимая проверка и статистика

До создания проверочных сценариев общим seal фиксируются решения всех методов во всех 20 условиях, хеши кода, каталогов и калибровочных сценариев. После этого создаётся новый банк из 4096 независимых полных партий на условие. Исходный и исправленные планы сравниваются на одинаковых сценариях. Отдельный независимый DES проверяет внешний выпуск партии; DAG и оригинальный S1 контролируют согласованность. Состав проверок и подвыборка полных трасс задаются до исполнения.

Основное семейство: 20 условий × пять пар D против N/L/S/T/G = 100 сравнений. Для каждого считаются целочисленные парные выигрыши и проигрыши. Четыре односторонние границы Клоппера—Пирсона с alpha=0,05/(4×100)=0,000125 дают общую внешнюю область уровня не ниже 95% для всех 100 разностей. Обычные 95%-е интервалы частот являются описательными интервалами отдельных условий.

Отдельно сообщаются: эффект осуществимой правки относительно исходного плана; её результат относительно сильных контрольных стратегий; согласованность и полные затраты S1/DAG. Положительная диагностика или снижение собственного показателя модели не заменяет внешний эффект выпуска. Отрицательный и неопределённый результат допустимы и не приводят к изменению исходного критерия.

## Затраты и завершённость

Измеряются чтение и проверка входа, построение каталога, создание сценариев, исходные прогоны, трассы, диагностические вмешательства, все рассмотренные правки, выбор, запись ответа и ранние пропуски. Учитываются неудачные процессы и тайм-ауты. Для каждого условия выполняется один полный вызов каждого метода на одном runner; повторяемость времени отдельного условия по одному измерению не заявляется. Первичная установка и сборка, общий вход и историческое построение исходных планов раскрываются отдельно; общие затраты не исчезают из полного итога при кэшировании.

Все исполнения, проверки и формирование отчёта выполняются на GitHub-hosted Actions. Суммарный бюджет кампании 72 runner-часа включает предыдущие этапы, сборки и ошибки. При невыполненных условиях, проверках или контролях статус серии PARTIAL. Полнота исполнения не означает подтверждение преимущества.

Для заранее определённой таблицы сравнительной пользы «сопоставимые затраты» означают не более 1,25 полной измеренной стоимости контроля при подтверждённо лучшем внешнем результате. «Тот же результат дешевле» устанавливается только для одного и того же физического плана с меньшей полной измеренной стоимостью; перекрытие интервалов частот не доказывает эквивалентность. Этот порог не меняется после просмотра результатов. Затраты D и идентичного D-DAG приводятся отдельно.

В проверочном банке DES и DAG выполняют все 4096 прогонов каждого уникального физического плана с независимой проверкой баланса работы и выпуска. S1 выполняет скалярную проверку всех 4096 исходов и полную проверку первых 16 трасс. Точные совпадения планов между методами не увеличивают статистическую выборку. Все выявленные несовпадения блокируют положительный вывод.

# Аналитические условия и совместный подбор плана и ремонта

Новая прикладная задача — получить конкретные планы и требования к ремонту, при которых вероятность выпуска всей партии к прежнему сроку не ниже 95%. Пользователь разрешил менять план и параметры ремонта. Станки, совместимость, партия, технологические зависимости, исходный C0 и срок d=1,1C0 сохраняются. Предыдущий отрицательный вывод о сравнительном преимуществе S1/SIMPAT не изменяется.

Основной инструмент — стандартные ограничения расписания и прямой DAG. Оригинальный S1 и независимый DES проверяют физические исходы. Сравнительная новизна и превосходство S1 здесь не заявляются.

## Разрешённое меню условий

От каждого из десяти зафиксированных CP-планов строятся до шести кандидатов: ограничения фактического структурного отличия 1, 4 и 16, цели минимальной номинальной длительности и минимальной максимальной нагрузки станка. Сохраняется исходный план. Каждая попытка CP ограничена 35 секундами, всё семейство — 240 секундами; незавершённые/ошибочные процессы сохраняются. Возврат UNKNOWN с известным допустимым исходным решением обозначается fallback, а не доказанным оптимумом.

Структурное отличие: число операций с изменённым назначением плюс число инверсий исходного порядка пар операций, оставшихся на своём исходном станке. Считается фактическое отличие конечного плана, а не число поисковых шагов. В отчёте обе компоненты сохраняются отдельно. Изменение времён вследствие структурной правки раскрывается полностью.

Исходный план обязан уже быть ранним. Для каждого кандидата из фактических назначений и очередей заново вычисляется раннее расписание. Скрытое сжатие произвольных CP-времён не считается улучшением с нулевым отличием. Дубликаты удаляются только по точному физическому расписанию. Допускается номинальная длительность до прежнего срока: ограничение длительности исходного CP-плана из старой серии не переносится.

Ремонт меняется общим для всех станков коэффициентом rho из {1;0,75;0,5;0,25;0,125;0,0625}. Среднее исходного экспоненциального ремонта равно 0,1C0 rho, длительность работоспособности — 2C0. Средние заданы до округления вверх с минимальным шагом5 ticks; в начале все станки исправны. Это ограниченное семейство требований, не оптимизация отдельных ремонтных политик каждого станка. Реальная возможность обеспечить эти средние и денежная цена неизвестны.

Для каждого rho заново строятся правильные renewal-циклы. Сокращение ремонта сдвигает будущие отказы; простои не просто обрезаются при сохранении будущих начал. Вложение траекторий и бинарный поиск не предполагаются. F1 остаётся независимым, F2 — смесью с независимой монетой на репликацию: общий календарь с вероятностью1/2, независимые календари с вероятностью1/2. Uniform rho сохраняет определение общего календаря.

## Аналитические условия

В объединённом графе технологических и машинных зависимостей прямой проход даёт ранние времена ES, обратный от срока — последние окончания LF. Для каждого станка обязательная работа W_m должна поместиться в доступное время A_m(0,d). Это необходимое условие.

Более точное необходимое условие для окна[a,b]: операция i должна получить внутри него не меньше e_i=max(0,p_i−max(0,a−ES_i)−max(0,LF_i−b)). Сумма e_i операций данного станка не должна превышать его доступное время в окне. До случайных испытаний выбираются32 окна на станок по убыванию требуемой доли обслуживания, затем по запасу и границам окна. Проверка ограниченного числа окон не является полным условием выполнимости.

Достаточный сертификат: A_all(d)>=C_nom, где A_all — время, когда ВСЕ используемые станки одновременно исправны. Это d минус длина ОБЪЕДИНЕНИЯ их простоев, а не минимум отдельных доступных времён. Общая искусственная остановка всех станков даёт более медленную систему; ранний исходный план при реальной доступности завершается не позже. Для общей календарной ветви F2 условие становится точным. Эти утверждения применяются к нынешним нулевым releases, ранним расписаниям, единичной скорости, продолжению обработки после ремонта и неограниченным буферам.

Необходимые условия объясняют невозможность, достаточное — гарантированный успех данного сценария. Прохождение необходимого условия не доказывает успех. Аналитические флаги сверяются с независимым фактическим выпуском, а не объявляются производственным эффектом сами по себе.

## Полная сертификация меню

Все десять семейств планов и полная сетка rho фиксируются общим seal ДО создания случайных сценариев. Проверяются ВСЕ сочетания плана и rho для обоих законов. Старые открытые банки не используются.

На условие создаются8192 новых независимых сценария полной партии. Случайные числа могут переиспользоваться между зарегистрированными вариантами; это не увеличивает8192 независимых испытания каждого варианта. Для каждого сочетания независимый DES определяет внешний выпуск всей партии, прямой DAG проверяет все8192 исхода, оригинальный S1 проверяет заранее фиксированные первые128 скалярных исходов. Первые16 полных трасс каждого сочетания дополнительно сравниваются с проверкой физического баланса.

Пусть N — число всех сочетаний в общем seal, включая оба закона. До открытия банка устанавливается alpha=0,05/(2N). Для всех сочетаний строятся две односторонние точные биномиальные границы Клоппера—Пирсона. Совместное покрытие всех интервалов не ниже95% без требования независимости между вариантами.

Вариант подтверждённо удовлетворяет цели, если нижняя граница>=0,95; не удовлетворяет, если верхняя<0,95; иначе остаётся неопределённым. Все варианты публикуются. Из подтверждённых формируется Парето-меню по числу переназначений, инверсиям очередей и величине сокращения среднего ремонта. Это сертификация заранее фиксированного меню, а не независимая оценка после скрытого отбора по этому же банку.

Минимальность внутри меню подтверждается только если ВСЕ варианты, которые требуют не больше изменений по каждой компоненте и строго меньше хотя бы по одной, подтверждённо не достигают цели. Если среди них есть неопределённый вариант, минимальность не доказана. Глобальная оптимальность среди всех расписаний и параметров не заявляется.

Все построения, компиляции, проверки, симуляции, измерения и отчёты выполняются на стандартных GitHub-hosted Actions. Общий предел72runner-часа включает старые этапы, подготовку, ошибки и новые задачи. Любые невыполненные обязательства обозначаются PARTIAL. Наличие Парето-точек и проверяемость требований не изменяют прежний NOT_ESTABLISHED сравнительной гипотезы.

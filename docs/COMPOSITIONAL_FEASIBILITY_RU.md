# Пучковая композиция и новые алгебраические операции: проверка применимости

Проверяется исходная гипотеза: получить тот же сертифицированный производственный результат дешевле сильных прямых методов либо лучший результат при сопоставимой полной цене. Этот этап устанавливает математические предпосылки и размеры представления на десяти зафиксированных входах. Он не является новым решателем и не может подтвердить сравнительное преимущество по одним размерам таблиц.

Все численные сводки, проверки и отчёт выполняются в GitHub-hosted Actions. Используются существующие Mk01–Mk10; новые траектории, планы и обучение не создаются. Регистрируются три разбиения четырьмя блоками целых станков: последовательные идентификаторы, round-robin и балансировка по работе. Для фиксированного плана работа берётся по его назначениям; для свободного синтеза — потенциальная работа по всем альтернативам, делённая на число альтернатив. Балансировка — стандартное жадное LPT, без заявления оптимальности разбиения.

## Точная конструкция для фиксированного плана

Для каждой операции i сохраняется точная рекурсия времени завершения:

    c_i = finish_on_calendar(machine_i,
             max(planned_start_i, release_i, c_technological_predecessors,
                 c_previous_in_machine_queue), work_i).

Операции и целая очередь станка принадлежат одному блоку. На границе передаются завершения операций с технологическим преемником в другом блоке. Для конкретных граничных времён W_b есть суммарный вес календарей собственных станков, при которых ВСЕ локальные рекурсии выполнены точно. Не достаточно только неравенств допустимости: они могли бы многократно посчитать одну историю с разными временами.

Объединённый фиксированный граф ацикличен. Поэтому каждой истории соответствует ровно один вектор завершений. При F1 календари разных станков независимы и каждый их вес принадлежит ровно одному W_b. Сумма произведений W_b по согласованным граничным временам даёт вероятность успешного исполнения без многократного счёта. Для события успеха все обязательные операции завершаются к сроку; можно ограничить времена необходимыми окнами healthy earliest/latest. После фиксации входных времён локальные выходные времена всё ещё могут быть зависимы.

Если у операции один технологический преемник, её время связывает не более двух блоков. Тогда можно собрать все координаты одной пары блоков в один интерфейс и получить четыре таблицы формы K4. Отсутствующие связи имеют домен размера один. Это точное соответствие формы, а не гарантия компактности: один интерфейс может содержать множество времён разных передач и повторных посещений.

## Округлённые отказы и вероятностные веса

При Δ=5 и округлении вверх длительность Δ*ceil(Exp(mean)/Δ) в единицах Δ геометрическая: Pr(L=l)=q^(l-1)(1-q), q=exp(-Δ/mean). В начале все станки работают. До T=floor(d/Δ) имеется конечный алфавит состояний; для одного станка все 2^(T-1) двоичные up/down последовательности после первого up-слота имеют положительную вероятность. Это не замена непрерывного закона равновероятными битами.

При исходных средних 2C0 и 0,1C0 положим q=exp(-Δ/(2C0)). Вероятности сохранения up/down равны q и q^20; при четверном ускорении ремонта — q и q^80. Для фиксированного плана конечная вероятность F1 выражается полиномом от q с целочисленными коэффициентами. Это устанавливает существование аналитического представления, но не дешёвый способ получения коэффициентов. При независимом изменении средних естественен многомерный полином. Подстановка одного q не должна одновременно менять неизменяемый закон работы до отказа.

F2 — смесь независимой и общей ветвей, веса каждой по 1/2. Общую историю нельзя копировать как независимые вероятности четырёх блоков. Для zero-release earliest-плана, когда planned_start избыточен при задержках, общая ветвь имеет более сильный простой контроль: успех эквивалентен накопленному рабочему времени общего календаря не меньше healthy makespan. Его распределение считается обычной Markov/reliability DP. Это известное упрощение, не вклад ETH или пучков.

F2SI не подменяется F2: пусть r — общая исходная экспоненциальная длительность ремонта, а L=ceil(r/Δ) — её целое число слотов. При ускорении ровно в четыре раза fast-длительность в слотах равна ceil(r/(4Δ))=ceil(L/4). Общие последовательности инноваций имеют один общий вес и собственные часы каждого станка. Формальное конечное представление существует, но оно не становится независимыми локальными priors; текущая перепись не вычисляет его сокращённые таблицы.

## Свободный синтез

Переменная операции — (назначенный станок, плановое начало, плановый конец), конец однозначно задаётся выбранной длительностью. Локальные факторы включают технологический порядок, releases и условный NoOverlap для каждого потенциально совместимого станка. Все альтернативы сохранены; старые CP-очереди и planned_start не ограничивают синтез.

Для номинального синтеза перепись использует gcd всех альтернативных длительностей: при нулевых releases для каждого допустимого назначения и порядка раннее расписание лежит на этой сетке, поэтому существование плана сохраняется. Так избегается искусственное раздувание таблиц временами бессодержательного простоя. Это множество достаточных представителей, не подсчёт всех исходных расписаний. Фактические завершения при отказах сохраняют исходный шаг Δ=5 и не округляются к gcd.

Машинный фактор размещён в блоке станка, маршрутные факторы — в заранее заданном блоке заказа. Общая операция может встречаться в трёх и четырёх блоках. Такая связь не является одним независимым парным интерфейсом K4. Копирование с равенствами возможно, но увеличивает состояние. Глобальное сечение этих отношений даёт допустимый номинальный план, не автоматически оптимальный и не вероятностно сертифицированный.

Для устойчивого синтеза план выбирается до будущих отказов: max_plan sum_failures p*Y. Перестановка max и суммы допустила бы ясновидящее перепланирование. Вероятность одного фиксированного плана и оптимизация по планам остаются разными задачами.

## Что измеряется и что не следует из переписи

Для каждого из 60 профилей разбиения сохраняются участники границ, размеры доменов, число связей трёх/четырёх блоков и размеры плотных локальных таблиц. Оценка восьми байт на ячейку — оптимистическая иллюстрация размещения, не достаточная точность сертификата. Произведение доменов не есть нижняя граница сжатого представления и не число достижимых состояний.

Общий бюджет исходных четырёх таблиц проверяется по сумме их размеров; максимальная отдельная таблица сохраняется отдельно. Для обычной свёртки четырёх готовых факторов проверяются три разных 2|2-разреза и размеры пересекающих переменных. Это оценка материализованных плотных промежуточных данных, не нижняя граница арифметической сложности всех алгоритмов.

Для фиксированных блоков также сохраняется верхняя оболочка состояний локальной forward-DP по head/remaining-work/up-down станков. Это обычный Markov-контроль и верхняя, а не нижняя оценка; достижимость не утверждается. Одного малого графа межблочных связей недостаточно — важны домены, зависимость координат, построение W_b и точность.

Signed Network Sums используют знаковую сумму сетей с разными порядками свёртки. Алгебраическая оценка для уже заданных таблиц не включает производственную компиляцию. Сильнейшие показатели в свежей работе зависят от новых результатов по матричному умножению; они не являются практическим временем. Для вероятностей нужны точная символическая арифметика либо доказанная ошибка при вычислении экспонент и компенсации знаковых членов. Сравнение включает обычные устранение переменных, BDD, разреженные/низкоранговые методы и прямой DAG/MC.
